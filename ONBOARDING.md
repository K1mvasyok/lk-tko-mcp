# lk-tko-mcp — быстрый старт для разработчиков

MCP-сервер, который даёт Claude Code инструментальный доступ к системе
ЛК (lk-tko-v2) — вместо ручных curl/Groovy для рутинных проверок можно
просто спросить у Claude «найди контрагента по ИНН …» и получить
реальный ответ из REST API тестового контура.

Полная архитектура и план развития — в [README.md](README.md). Здесь —
только то, что нужно, чтобы поднять рабочую копию у себя.

## Требования

- [uv](https://docs.astral.sh/uv/) — менеджер зависимостей Python
- Доступ к тестовому контуру lk-tko-v2 (VPN/SSH-туннель, как для обычной
  разработки CUBA-проекта) + запущенный локально сервер lk-tko-v2
- Node.js LTS — **опционально**, только если хочешь ручной UI (MCP
  Inspector) для тестирования tools. Для обычной работы через Claude
  Code не нужен.
- Claude Code (`claude` CLI). Если у тебя Claude Desktop — CLI уже
  встроен, просто без него в PATH: ищи
  `%APPDATA%\Claude\claude-code\<версия>\claude.exe`.

## Установка (5 шагов)

```bash
# 1. Получить код проекта (скопировать папку или git clone, если уже в репозитории)
cd lk-tko-mcp

# 2. Поставить зависимости — venv создастся автоматически
uv sync

# 3. Завести свой .env
cp .env.example .env
```

**4. Заполнить `.env`.** Пять переменных:

| Переменная | Где взять |
|---|---|
| `LK_REST_BASE_URL` | `http://localhost:8080` — если сам поднимаешь lk-tko-v2 локально (как в `curls.txt` репозитория lk-tko-v2) |
| `LK_REST_CLIENT_ID` | `modules/web/src/com/groupstp/rtneo/web-app.properties` → `cuba.rest.client.id` |
| `LK_REST_CLIENT_SECRET` | там же → `cuba.rest.client.secret`, **без префикса `{noop}`** — бери только то, что после него |
| `LK_USERNAME` / `LK_PASSWORD` | твой личный логин/пароль на тестовом контуре lk-tko-v2 |

`.env` не коммитится, ротировать/расшаривать эти значения через чат или
общий канал не нужно — они у каждого разработчика уже есть в своей
копии lk-tko-v2.

```bash
# 5. Подключить к Claude Code
claude mcp add lk-tko-mcp -- uv run run.py
claude mcp list   # должно показать lk-tko-mcp ... ✔ Connected
```

Если `claude` не распознаётся как команда — используй полный путь до
`claude.exe` (см. «Требования» выше) один раз для `mcp add`, дальше
регистрация сохранится и полный путь больше не понадобится.

## Проверка

Открой сессию Claude Code в этой папке и спроси:
«используй lk-tko-mcp, найди контрагента по ИНН `<реальный ИНН из тестового контура>`».
Должен появиться вызов `lk-tko-mcp → get_contragent_status` с реальными
данными.

Для ручной проверки без Claude (нужен Node.js):
```bash
uv run mcp dev run.py
```
Откроется MCP Inspector в браузере — там можно вызывать tools руками
и видеть сырой JSON-ответ.

## Частые грабли

- **`uv run mcp dev run.py` → `Failed to spawn: mcp`** — команда
  запущена не из папки проекта. Сначала `cd` в `lk-tko-mcp`.
- **`ReadTimeout` при вызове tool** — не поднят SSH-туннель/VPN до
  тестовой БД, либо не запущен локально сам сервер lk-tko-v2
  (`LK_REST_BASE_URL` никто не слушает).
- **`PORT IS IN USE` при повторном запуске Inspector** — где-то уже
  висит предыдущий процесс (`node`/`uv`). Останови его (`Ctrl+C` в том
  терминале, где запускал, либо через диспетчер задач) и запусти заново.
- **`node`/`npx` только что установил, а команда всё равно не находит** —
  открой новый терминал (уже запущенные не подхватывают обновлённый PATH).
